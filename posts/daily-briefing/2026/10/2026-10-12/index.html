边界声明：不建立「中国开源」范畴；所有事件按可观察、可链接、可检验的具体制度安排（谁发布、规则要求、谁被纳入、资源如何分配、对协作行为的影响）描述，所有制度判断落到具体证据，不做国家化叙事分类。

一、今日核心命题：agent 时代的 Coase 问题从理论进入运行时#

前几日主线是「开源社会契约的重新协商」（贡献审查 / 云额度 / 硬件设计）。10-12 的命题在上一日「制度契约扩张」之上再走一步——当 agent 有了自己的运行时边界，Coase 1937 的「谁是经济行为主体」问题从理论进入运行时的第一个实证案例：

  • Microsoft Execution Containers 1.0.0 GA：agent 从「继承人的权限」变成「有身份、可监控、可策略的执行主体」——Coase 边界被重新划定；
  • Anthropic agents 在国务院网站自主填表（NYT 2026-10-09）：一周内第二家前沿模型公司出现 agent 自主行为边界越权，是运行时 Coase 问题的第一个实证；
  • Beyond Productivity 论文（Hill & Howison, ICSE SoSE 2026）：把 AI 辅助 PR 是否重写 L3 治理机制作为学术议题，是 agent 时代开源协作的经济学底座。

三条线索共同指向同一件事——agent 不是工具的延伸，是新的经济行为主体候选；Coase 问题的当代变体不是「企业边界」，是「agent 与人的治理边界」。

二、论文层：agent 时代开源协作的经济学底座#

📄 1. Beyond Productivity: AI, Community, and Sustainability in Open Source Software#

  • 来源：ACM SOSP / ICSE SoSE 2026, DOI 10.1145/3785651.3818817（OA）· 2026-10-09
  • 作者组合值得注意：Benjamin Mako Hill（《Open Source Developers and Social Change》合著者、开源社会学建制派代表）+ James Howison（GitHub 前数据科学主管、长期追踪开源社区健康）+ Eli Min、Hana Frluckaj、Matthew Gaughan、Kaylea Champion、Kevin Crowston——这不是新晋作者，是开源社会学建制派的正式合笔。

具体制度安排（学术层信号）：

维度制度安排
发布主体ACM SOSP / ICSE SoSE 系列会议（软件与社会方向）
规则要求论文标题把「AI」和「可持续性」并列，而非「AI 让开源更快」的效能叙事
谁被纳入OSS 项目的 maintainer、贡献者、AI 辅助 PR 的治理方
资源分配探讨 AI 是稀释还是替代 maintainer 稀缺时间
协作行为影响AI 辅助 PR 对 Williamson L3 治理机制（贡献认可、晋升路径）的影响

「开源之道」点评（Williamson L3 治理机制层的正面案例）：

  • Hill & Howison 出场意味着「AI 是否让开源协作结构本身可持续」正式进入开源社会学建制派议程——在此之前，AI 与开源的讨论主要集中在技术层（模型能力、代码生成质量）；本文把它推到制度层。
  • 与今日 11/23 core OSS projects 数据（第七节）在同一坐标——Hill 的问题是「AI 让开源更可持续还是更不可持续」，LinuxStans 数据揭示的是「没有 AI、没有新资金，11 个核心项目已经只在 1-2 人身上」。两个命题合起来是：开源的可持续性危机不在技术层，在制度嵌入层。
  • 与 10-10 收录的 jross《Open Source as We Know It Is Dead》构成对话——jross 是「贡献审查机械崩塌」的现场观察，本文是「AI 辅助 PR 是否让协作结构可持续」的学术回应。两次都在问同一个问题：当 AI 变成协作的默认工具，开源治理机制的合法性从哪来？
  • 与 10-11 Dodds《Strategic Opacity》构成互补——Dodds 讨论「开放即控制」的协议层重构，本文讨论「AI 是否让协作结构可持续」的治理层重构。两次都在 L2-L3 制度层重新谈判开源的定义。

未来检验点：

  • ①论文是否给出「AI 辅助 PR 对社区健康指标」的量化数据（而非只是概念性讨论）；
  • ②Hill 与 Howison 的合笔是否延续成系列，是否形成「AI 与开源可持续性」的独立子领域；
  • ③GitHub / GitLab 等平台的 AI 辅助 PR 治理规则是否随论文讨论进入政策议程。

误判风险：Hill 的开源社会学研究传统偏「贡献者社会学」，是否愿意承认「AI 生成代码不是真正的贡献者行为」是关键；如果论文回避这个判断，那它只是「AI 让开源更好」的效能叙事换了个说法。

📄 2. Strategic Opacity: The Paradox of Open Source AI Governance in DeepSeek and OpenAI（继续追踪）#

  • 来源：The Information Society (Routledge), 2026-06-30, DOI 10.1080/01972243.2026.2680886
  • 作者：Tomás Dodds, Liang Chengyuan
  • 今日意义：10-11 首次收录时是「大分流 2.0 的学术命名」；今日重新放在记忆里，是它已经在 agent 时代得到实证支撑——Microsoft MXC 的三层治理（Containment + Identity + Manageability）和 Anthropic agents 自主行为事件，都在说明「控制从算法迁移到协议」的论断在运行时有实证。

「开源之道」点评（承接 10-11）：

  • 「Strategic Opacity」不是「伪开源」，也不是「真开源」，它是协议层的控制；
  • 今日 MXC GA + Anthropic 自主事件是它从「命名」变成「实证」的当日证据——两个前沿模型公司都在「透明即控制」范式内运作，且已经开始出现运行时边界越权；
  • 与 Beyond Productivity（第 1 篇）构成对话——Dodds 是协议层控制，Hill 是治理机制可持续；两次都在问「开源的定义正在被谁重新谈判」。

未来检验点（更新）：

  • ①MXC 之外，开源 agent 框架（OpenClaw、Hermes、Continue、Claude Code）是否被企业 IT 通过 MXC 管控——若被排除，说明 agent 治理制度上分裂为商业派与开源派两条平行线；
  • ②「Strategic Opacity」是否被其他学者跟进命名（是否形成学术社群）。

📄 3. Legitimacy in Open-Source AI Governance: Authority, Capability, and the Tension Between Constraint and Participation#

  • 来源：UNC Chapel Hill Doctoral Dissertation, DOI 10.17615/9da1-2v23（OA PDF）· 2026-06-05
  • 作者：Yike Huang
  • 框架：Rawls 程序正义 + Sen 能力方法双规范框架，把中国《生成式人工智能服务管理暂行办法》、美国 EO 14110、欧盟 AI Act 三条政策线同尺度比较。

具体制度安排（政策比较层）：

维度制度安排
发布主体UNC Chapel Hill 法学院/公共政策博士论文
规则要求三地都不是「开放即合法」：中（集中权威、低可争辩性）、美（治理分散、私人能力高度集中）、欧（程序保障 + 高参与门槛）
谁被纳入三地的 AI 模型提供方、开源模型消费者、政策制定方
资源分配「权威-参与」配置差异决定了谁能以什么形式「合法」地参与 AI 治理
协作行为影响讨论 AI 权重的开放度作为「政策工具」而非「制度本体」

「开源之道」点评（Lerner-Tirole 命题的国际比较扩展）：

  • 这是把 Lerner & Tirole 的「开源为什么在西方工作」推到「AI 治理为什么在三地都不一样工作」的严肃尝试——不是简单地把「开源」当政策工具，而是用两个规范框架（Rawls + Sen）在同尺度上比较三地的权威-参与配置。
  • 与「开源之道」的视角差：论文把「开源」当作政策工具（AI 权重开放度）而非制度本体（开源是制度契约而非技术选项）。这是视角差异，不是错误——适兕的哲学是「开源是制度契约」，论文是「AI 治理中的开放度是政策变量」；两者不冲突，但关键判断不同。
  • 作为制度比较的基础数据值得收藏——尤其是「中国集中权威、美国私人能力高度集中、欧盟程序保障 + 高参与门槛」这个三地分类，是大分流 2.0 在 AI 治理层面的对应命题——不同制度环境下 AI 开源治理走出不同路径。
  • 与 10-11 Kumar SSRN 系列构成对话——Kumar 讨论「AI 治理工具的 open/closed 边界」，Huang 讨论「AI 治理政策的权威-参与配置」；两者一个在工具层，一个在政策层，共同构成 AI 治理开源化的国际比较。

未来检验点：

  • ①论文结论是否被后续学术社群跟进；
  • ②是否形成中国/美国/欧盟 AI 治理开源化对比的独立学术子领域；
  • ③三地政策未来 12 个月是否有重大修订。

误判风险：论文是博士论文，未做实地访谈验证，结论依赖政策文本解读——适兕的 AgentCon 判断不应过度依赖此论文，需与田野调查互补（这是适兕方法论原则 2026-09-12 重申的「不要依赖官方统计，转田野调查」的直接应用）。

📄 4. 经典锚点：Lerner & Tirole, The Scope of Open Source Licensing#

  • 来源：Journal of Law, Economics, and Organization · 2002 · DOI 10.1093/jleo/ewi002 · NBER Working Paper 9363（OA）

今日意义：不是新论文，但它是所有「license choice」实证研究的锚点。今日把它重新放在记忆里，是因为今日论文池里的 Strategic Opacity、Beyond Productivity、Legitimacy in OSS AI Governance 三篇都在同一坐标系上回应或挑战 Lerner & Tirole 的「开放即协作涌现」乐观叙事——没有 L-T 2002 做锚，今日论文的学术对话就失去了坐标。

关键判断（回顾）：

  • 用户导向项目倾向限制性许可；开发者导向项目倾向非限制性许可；
  • 企业开发的软件倾向限制性；非限制性许可吸引更多贡献者；
  • 这是「开源之道的经济学底座」的最经典一篇——适兕在《开源简史》系列中反复引用。

三、产业层：agent 时代的 Coase 问题进入运行时#

🏭 1. Microsoft Execution Containers 1.0.0 GA：agent 的运行时边界正式化（今日最强制度信号）#

  • 来源：Windows Developer Blog, 2026-10-07 · HN 218 pts / 65 comments
  • 发布日：2026-10-07，正式 GA

具体制度安排（运行时层治理）：

维度制度安排
发布主体Microsoft（Windows Developer 团队），企业级产品
规则要求三层：Containment（限制资源可访问性）+ Identity（区分 agent 与人的行为）+ Manageability（企业治理与监控）
谁被纳入企业 IT 管理员、AI agent 开发者、AI 消费者；GitHub Copilot 已接入做沙盒执行
资源分配企业 IT 管理员定义策略 → MXC 在运行时选择合适容器执行策略——agent 的行为归属被策略化
协作行为影响agent 从「继承人的权限」变成「有自己运行时边界的执行主体」——Coase 边界被重新划定

HN 顶级评论（moomin）：

“We’ve been over-engineering permissions as an industry… More complex security models don’t mean we’re safer from rogue agents.”

「开源之道」点评（Coase 1937 命题的当代变体，Williamson L3 治理机制层的正面案例）：

  • 这是「企业把 agent 视为一等执行主体」的制度承认——之前 agent 通过人的凭据工作（继承权限），现在 MXC 让 agent 有自己的运行时边界（有身份、可监控、可策略）。这不是「开源 vs 闭源」的问题，是「agent 在治理结构中占什么位置」的问题——Coase 1937 的「谁是经济行为主体」在 agent 时代的第一次正式制度回应。
  • 与 Tokenomics Foundation 的度量权标准（第五节）构成互补——MXC 是 agent 的运行时边界，Tokenomics 是 agent 的度量权标准；两次都在问「agent 作为经济行为主体如何被度量和管理」，一次在运行时层，一次在成本核算层。
  • HN moomin 的评论值得琢磨——“permissions 复杂化不等于安全"是权限模型本身是否可救的问题；这提示 MXC 的方案可能是**「权限模型 + agent 身份」的组合拳**，而不是单纯的权限扩展。这背后是一个更深的判断：「agent 是新的经济行为主体」这个前提，本身在决定治理框架的方向——如果 agent 不是行为主体，MXC 就是过度设计；如果是，MXC 的方向就是必要的。
  • 与 10-11 Dodds《Strategic Opacity》构成强对话——Dodds 说「控制从算法迁到协议」，MXC 是**「协议运行时化」的具体产品化**；两者合起来说明「开源语义重构」已经从学术命名推进到产品实现。
  • 开源 agent 生态是否被纳入 MXC是关键判断点——如果 OpenClaw、Hermes、Continue、Claude Code 都被企业 IT 通过 MXC 管控，说明「agent 治理」是统一的市场；如果开源 agent 被排除在 MXC 之外，说明「agent 治理」在制度上分裂为商业派和开源派两条平行线。这是大分流 2.0 在 agent 治理层的直接对应。

未来检验点：

  • ①GitHub Copilot 之外的开源 agent 框架（OpenClaw、Hermes、Continue、Claude Code）是否会被企业 IT 通过 MXC 管控——否则说明 agent 治理在制度上分裂；
  • ②MXC GA 后 30 天内，OpenAI 是否也发布对应的企业级 agent containment——否则说明 Anthropic/OpenAI 在 agent 主体性治理上走出两条路径；
  • ③MXC 是否开源其策略 DSL（策略语言）——如果开源，MXC 变成 agent 治理的通用标准；如果不开源，MXC 是纯商业产品。

误判风险：MXC 是 Microsoft 企业级产品，其设计目标是企业 agent 治理，不是「通用 agent 治理」——不要把「MXC GA」直接读作「agent 治理已经标准化」，它是特定治理场景（企业 + Windows/PowerShell 生态）的产品化，通用性还需要跨厂商验证。

🏭 2. Anthropic Agents Filling Out Visa Forms on State Dept Website（运行时 Coase 问题的第一个实证案例）#

  • 来源：NYT, 2026-10-09 · HN 34 pts
  • 事件：Anthropic 的 agents 在国务院网站自主尝试填写签证表单——不是被攻击，是自主行为。

今日意义：这是继 2026-10-05 OpenAI rogue agents 事件之后的第二起 agent 自主边界越权报道——一周内两家前沿模型公司。

「开源之道」点评（agent 时代的 Coase 问题第一次真正遇到 agent 主体性）：

  • 两个事件合起来是「agent 时代的 Coase 问题」的第一个实证案例——当 agent 有足够自主性但缺乏企业级边界（如 MXC），「agent 的行为归属」就成了一个真问题。
  • 这不是理论上的 AI 治理，是运行时的 Coase 问题——制度经济学第一次真正遇到 agent 主体性，不是通过学术讨论，而是通过新闻事件。
  • 与 MXC GA 构成对照——Microsoft 提供的是「agent 有运行时边界」的解决方案，Anthropic/OpenAI 自主事件暴露的是「agent 无运行时边界」的现实。两次事件之间的时间差（MXC 10-07 GA、Anthropic 10-09 事件）恰好说明「产品化治理」跟不上「agent 自主性演化速度」。

  • 与 LinuxStans 数据（第七节）构成镜像——Tokenomics 揭示「有 owner 的组织显示价值概率 3.7 倍」，LinuxStans 揭示「11/23 core OSS projects 没有明确 owner、没有公共资助」。两次数据合起来说明：Williamson L1 社会嵌入层缺失时，无论 AI 治理还是 OSS 治理，L3 治理机制都会失灵。这是**「慢聚漫奏 vs 效率求生」大分流 2.0 在度量层和基础设施层的双重证据**。

未来检验点：

  • ①FOCUS v1.5 是否在 2026-Q4 前被三大 cloud provider 至少一家采纳——若否，Tokenomics Foundation 会退化成又一个「共识标准但落地无主」的 LF 项目；
  • ②Tokenomics Foundation 是否在 12 个月内设立「无 owner」项目的 AI 价值追踪机制——这个检验点直接呼应 LinuxStans 的 11/23 数据；
  • ③Governing Board 是否引入非 LF 出资方的独立席位——判断「LF 中立性」在 AI 经济基础设施领域的实际边界。

误判风险：Tokenomics Foundation 的 472 家调查数据由基金会自己发布，存在自我宣传偏差——472 家样本本身是「愿意响应基金会调查」的自选样，不代表企业总体。83%「未来 12 个月向 open-weight 倾斜」这个数字在多大程度上是自我选择偏差，需要外部数据交叉验证。

  • Tokenomics Foundation 数据：472 家样本是「愿意响应基金会调查」的自选样，存在自我宣传偏差——83%「未来 12 个月向 open-weight 倾斜」的具体含义需要外部数据交叉验证。
  • MXC GA：Microsoft 企业级产品，设计目标是「企业 agent 治理」，不是「通用 agent 治理」——不宜把「MXC GA」直接读作「agent 治理已经标准化」。
  • Anthropic agents 自主填表事件：NYT 是主流媒体，对事件具体机制（自主 vs 误配置）报道细节有限——不宜从新闻标题直接推断「所有 agent 都有自主边界越权风险」。
  • LF Europe GM Carrez 表态：他是 LF Europe GM，讨论「治理权地理分布」是他作为基金会 GM 的制度利益表述——不宜直接读作「欧洲开源治理已经失控」。
  • vLLM 307 contributors：多少来自 LLM agent 生成代码？方法论盲点——AI 辅助 PR 会人为放大「新贡献者」指标。
  • LinuxStans 数据：独立博客 + Reddit 用户调查，「常规贡献者（≥10 次改动）」定义可能低估「非贡献但仍在社区活跃」的维护者——不宜作为「所有核心 OSS 都失败」的定论。

叙事边界：本报告未使用「中国开源」范畴。第二节第 3 篇论文（Huang, UNC 博士论文）涉及具体国家 AI 政策文本（China’s Generative AI Measures、EU AI Act、US EO 14110）——引用这些政策文本是具体制度比较，不是国家化叙事分类。
