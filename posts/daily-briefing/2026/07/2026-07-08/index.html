  • 作者: Jihao Liu, Guoxiong Gao 等
  • 摘要要点: 基于 LLM 的数学推理 Agent 编排框架，使用事实图记忆（Fact-Graph Memory）协调并行推理路径，已能在研究级数学问题上取得突破。

🔍 开源之道视角解读#

1. MCP 协议无状态化：协议的"制度变迁"

MCP 从有状态双向协议到无状态请求/响应模型的转变，是典型的制度演化案例。从新制度经济学视角看，有状态协议意味着复杂的会话管理负担（高交易成本），而无状态设计降低了协议实现的门槛，促进了更多参与者进入生态。这与 Coase 定理的核心洞察一致——降低交易成本有助于资源更有效配置。值得关注的是，AAIF 作为 Linux Foundation 下的治理主体，如何平衡"协议稳定性"（已有 1.x 部署的投资锁定）与"协议演进"（2.0 的突破性变更）——这是一个典型的路径依赖 vs 制度创新张力。

2. Skills Over MCP：Agent 技能市场的制度基础设施

Skills Over MCP WG 的工作本质上是在构建一个Agent 技能的知识市场。从制度分析框架（IAD）看，这涉及：

  • 边界规则：谁可以发布技能？谁可以消费？
  • 信息规则：技能元数据标准（SKILL.md 格式）、URI 寻址方案
  • 分配规则：技能如何被发现、评分、推荐
  • 这与开源生态中 npm/PyPI 等包管理器的治理逻辑高度同构，但面向的是 Agent 而非人类开发者

3. 米其林 OSPO 建设：传统工业企业的制度转型

米其林（136年历史）的 OSPO 建设，是制度企业家（institutional entrepreneurship）的典型案例。传统封闭制造企业建立开源治理体系，需要克服组织惯性（organizational inertia）、改变内部激励机制、建立新的合规流程。米其林在 FOSS Backstage 的分享，本质上是在输出一种制度模板（institutional template）——为其他传统工业企业提供可复制的 OSPO 建设路径。这反映了 OSPO 从"IT 部门实践"向"企业战略基础设施"的制度化过程。

4. EU CRA 对开源供应链的正式制度冲击

EU Cyber Resilience Act 的落地是开源领域最重大的正式制度变迁。CRA 将合规责任延伸到整个供应链，改变了开源软件"免费无责"的隐含契约。从知识社会学视角，这反映了开源从"草根运动"到"受监管基础设施"的正当性转型——当开源成为关键基础设施，社会必然要求更正式的责任分配机制。SBOM（软件物料清单）作为信息基础设施，本质上是降低供应链信息不对称的制度装置。

5. 2026 开源状态报告：开源从"战术"到"战略"的制度化

报告指出企业心态已从"采用开源降成本"转向"开源是战略基础设施"，这标志着开源在组织场域（organizational field）中位置的制度化跃迁。从 DiMaggio & Powell 的同构性理论看，这种转变可能是三种同构压力共同作用的结果：强制同构（CRA 等法规）、模仿同构（同行企业都在建 OSPO）、规范同构（专业社区的标准推广）。

📊 趋势观察#

  1. Agent 协议治理成为新前沿：MCP 2.0 + Skills Over MCP + AAIF 三者构成 Agent 生态的协议层、应用层、治理层三层架构，2026年下半年值得持续关注。这与 1990 年代互联网协议栈的治理演化有惊人的相似性。

  2. OSPO 从科技公司扩散到传统工业：米其林等制造企业的 OSPO 建设，表明开源治理正在从 IT 行业向更广泛的工业领域扩散。这是开源制度化的深层次信号。

  3. 监管合规驱动开源治理工具化：CRA 的截止日期推动 SBOM、SCA、SLSA 等工具从"最佳实践"变为"合规必需品"。OpenSSF 等组织的治理标准正在被监管框架引用，形成"软法→硬法"的制度转化路径。

  4. 开源 AI 定义进入实施阶段：OSI 的 OSAID 1.0 发布后，行业正在实际测试其边界——什么算"开源 AI"，什么不算。这将是 2026 年下半年最值得关注的制度争论之一。

  5. AAIF 的全球扩张：从 MCP Dev Summit 覆盖十城市、AGNTCon + MCPCon 双线并行来看，AAIF 正在快速建立全球 Agent 开发生态的制度基础设施，其治理结构（创始成员 Anthropic/Block/OpenAI 的权重 vs 社区治理）将持续塑造 Agent 生态的发展方向。
