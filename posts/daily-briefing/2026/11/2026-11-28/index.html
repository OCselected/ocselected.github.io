「开源之道」 2026-11-28 搜集事件和材料#

今天两件事指向同一个位置：闸口——当评价可以被自动化之后，被评价的人会怎么变。

① 治理机器比它治理的人跑得快：3,937 个仓库、643,272 个 PR 的 DID 证据显示，接上 AI 评审之后，维护者每个 PR 上的评审评论 +14%、承担的 PR 数 +10%；而人类提交的代码行数 −14.1%、改动文件数 −33.8%。人类看见口径可预测，于是把工作拆小。这不是退出项目，是退出项目的难的部分。

② Ladybird 的第一个 alpha 与五个月前关闭的 PR 入口在同一张时间轴上。它给出的理由，是我在开源项目里读到过的、对「AI 让贡献的信号价值归零」最直接的一次承认：**一个大 patch 曾经隐含大量付出，而那份付出曾是诚信的合理代理——这个假设不再成立了。**它的处方不是修输入端，是整体切断输入端。

两者合起来是一句：闸口可以改，河床不一定回得来。

📄 最新开源研究论文#

1. 治理机器比它治理的人跑得快：3,937 个仓库、97 万 PR 的 DID 证据#

论文：Feiyang (Amber) Xu、Poonacha K. Medappa、Murat M. Tunc（蒂尔堡大学），arXiv:2611.22793 [econ.GN]，2026-11-17 提交 链接：arXiv:2611.22793｜DOI 10.48550/arXiv.2611.22793 方法：把 GitHub 2025-02-26 上线的 Copilot Reviewer 当作准自然实验，用 Callaway–Sant’Anna 交错 DID（按 maintainer 层面定义处理组：689 位 treated / 1,902 位对照，3,937 个 Python 仓库，62,184 个 maintainer-月，643,272 个 PR 进入生存分析），再加 Cox 比例风险模型看合并速度。作者自注曾在 WISE / ICIS / INFORMS / CIST / SCECR 五场信息系统会议宣读，尚未见期刊卷期。

摘要：四条结论。

  • 评审者本人的负担不降反升：处理后 maintainer 每个 PR 上的评审评论数 +14%，承担的 PR 总数 +10%。
  • 人类贡献先涨后跌：第一波出现提交激增（lead-lag 图在 0 期后立即抬升），随后回落到对照组的下方。
  • 人类 PR 变小：代码行数 −14.1%（系数 −0.152，p<0.05）、改动文件 −33.8%、提交数 −15.9%；而 bot PR 的行数 +3.8%（p<0.05）。
  • 速度不对称：被人评审又被 Copilot 评审过的人类 PR，合并风险比 HR=1.042（p<0.01）；同样被 Copilot 评审的 bot PR 是 HR=0.785（合并可能性降 21.5%）。机制检验：PR 越大，Copilot 的速度优势越弱（交互项 HR=0.971，改动翻倍则相对优势降约 2.0%）。

文中最锋利的一句在讨论部分：When GenAI enhances the capability of knowledge production, the central challenge shifts from scarcity to overabundance of generated information.

为什么与「开源之道」相关：这是一篇罕见的、把「评价标准被自动化之后，被评价的人会怎么变」做成因果识别的论文。开源社区的功绩制从来不是自然状态，它是一台由人操作的筛选机器：谁提交、谁评审、谁被记住。Copilot Reviewer 做的事，是把这台机器的第一道闸口换成一只随时在线、口径统一、零边际成本的算法——而论文测量的正是换闸之后上游水流的变化。

结论是反直觉的：闸口变快了，但河床被改了。人类看见口径可预测，于是把工作拆小（−33.8% 的改动文件数是全文最刺眼的一个数）；拆小之后，那些需要跨模块判断、需要长时间酝酿、需要和评审者来回说服的工作，就不再被提交了。用赫希曼的话说，这不是「搭便车」，是 exit 的一种低强度形态：不是退出项目，是退出项目的难的部分。

「开源之道」点评：论文把「机器评审」当作一个中性的加速器来测量，但它实际测到的是制度的学习能力被单向地嫁接到了机器身上。人类贡献者学到的不是代码该写成什么样，而是「什么形状的提交能过那道闸」——这是工具理性最纯粹的一次胜利：规则越标准化，被规则塑造的人就越只在规则可测的维度上活着。

有两处必须指出。

第一，作者自己承认 bot PR 只占样本的极小部分（119 个 bot 账号中仅 13 个可算 agent bot，占总 PR 的 1.7%），所以 2026 年那波 agent 洪水还没有真正进入这条曲线。这意味着 1,000 万级的 agent PR 若真的涌进来，本文的估计很可能还是低估的。

第二，同一位作者的前作（Xu et al. 2025a, arXiv:2510.10165）标题是「AI 辅助编程提高技术债与维护负担」——同一批人不约而同地得出同一个方向的结论，本身就值得记一笔。

📰 开源动态摘要#

1. Ladybird 第一个 alpha：四年、从零写的引擎出闸，但这四年里它把提交入口关了一半#

来源：Ladybird 官方博客（2026-11-23，Andreas Kling）；GitHub Releases 2026.47.7 / 2026.47.8 / 2026.48.0；HN 11-27 两条独立帖（87 pts / 79 pts） 链接：ladybird.org/posts/alpha｜ladybird.org/news｜github.com/LadybirdBrowser/ladybird

摘要：11 月 23 日发布首个可下载 alpha（macOS / Linux），自动更新、滚动通道，四天内连发三个版本（最新版支持后台标签页卸载、可选哪些标签共享进程、新增 AppImage）。

技术底子是关键：自有引擎，不是 Chromium / WebKit / Gecko 的分叉——HTML / CSS / DOM / 布局 / 自写 JS 引擎 LibJS（含 JIT）/ LibWasm 全部从零实现，多进程 + 站点隔离沙箱，代码正在向 Rust 迁移，WebDriver 与 Firefox DevTools 协议可用。

治理结构：由美国 501(c)(3) 非营利 Ladybird Browser Initiative 运营，Kling 任总裁，资金全部来自赞助与捐赠，公开声明「赞助方对路线图没有发言权」「不卖董事会席位」「不做默认搜索引擎交易、不发代币」；赞助方含 Shopify、Cloudflare、37signals、FUTO、JetBrains、Proton VPN 与 Human Rights Foundation。作者自己写：「我们想被安全极客打！一个新浏览器会被反复打穿，这是过程的一部分，所以我们今天对安全性不做任何承诺。」

「开源之道」点评：真正的制度细节不在这份清单里，而在 2026-06-05 那篇《Changing How We Develop Ladybird》：「我们不再接受公开 pull request，代码只能由项目 maintainer 引入」，同时关闭全部在途 PR，并明说「不会为其他方式设一个影子贡献系统（issues、评论、邮件、fork 都不算上游评审队列）」。

理由极其坦白：「AI 工具把这个经济学很快地改掉了……一个大 patch 曾经隐含大量付出，而那份付出曾是诚信的合理代理。这个假设不再成立了。」

这是我在开源项目里读到过的、对『AI 让贡献的信号价值归零』最直接的一次承认——它承认的不是 AI 能力，而是功绩制的度量衡失效。而它的解法是把入口收窄到「能为后果负责的人」：责任先行，信任后置。

这在安全工程上完全站得住（浏览器跑的是全互联网的不可信输入），在制度上则是一笔必须记账的交换——独立性用赞助合同换，质量用开放准入换。而它与今天那篇论文读的是同一件事的两面：论文测量「闸口换了之后上游怎么变形」，Ladybird 则是「干脆把闸口焊死」的处方。

摘要：榜单前列是 Tell HN: Happy Thanksgiving 713 pts、AI made self-hosting fun again 1,011 pts、Hard Drive pricing has gotten bad 519 pts、Company Culture = Slack Emoji ÷ √Headcount 527 pts、Nextcloud Office Desktop app 448 pts、Intel One Mono 572 pts、AMD-specific fork of llama.cpp 425 pts、Ladybird alpha 两帖合计 166 pts。

开源相关者几乎全是产品与工具：自建服务、办公套件、字体、推理引擎的硬件特化分叉。唯一进入治理层的是 Ladybird 的 alpha。

「开源之道」点评：值得记一笔的不是内容，是形状：当天除 Ladybird 外，前十热帖里没有一件涉及许可证、治理权、基金会或资助结构。

而 11-17 那篇《We don’t need more apps, we need better open source》（355 pts / 264 comments）恰好说出了这个形状的反面——社区情绪已经从「多做工具」转向「少做、做好」。AI made self-hosting fun again 是同一股气味的另一面：当分发通路（App Store、SaaS）开始不可靠，用户把东西搬回自己机器上，而「搬回去」这件事的技术前提恰恰是开源。

这不是开源治理的胜利，是开源的可用性在被外包的风险推着升值——和前几天简报里 FSNotes 被苹果下架的案例是同一根链条的两端。

🔍 Project Pulse：LadybirdBrowser/ladybird —— 69,692 星、47 个具名贡献者、一个浏览器，和入口关闭五个月后的真实切面#

项目：Ladybird（BSD-2-Clause，2024-05-30 建仓，69,692★ / 3,339 fork / 637 open issues，2026-11-27 18:25 UTC 仍有推送）

为什么今天深看它：本周它同时完成了两件在制度上互相拉扯的事——发布（第一个 alpha，面向真实用户）和封口（五个月前关闭公开 PR）。只看新闻会说「新的独立浏览器引擎来了」；只看那篇 6 月的公告会说「一个开源项目关掉了开源」。把两边放到同一张时间轴上，才看得见它到底在赌什么。

【L1 · 发布节奏】

4 天 3 个版本（11-23 2026.47.7、11-25 2026.47.8、11-26 2026.48.0），全部由 gmta 发布，ladybird-backport[bot] 自动把 master 的修复回灌到 release 分支（近 100 个 PR 里 27 个来自这个 bot）。

节奏健康，而且稳定得可疑地早：alpha 前五个月就进入「发布即滚动更新」的状态。分支模型写得很清楚——安全修复进 master，再回灌最新 release 分支（SECURITY.md「Supported versions」节），这是一份被明确写成规则的发布承诺。

【L2 · 治理结构：入口关闭五个月后的真实断面】

数据全部来自 GitHub API 实测。

  • 贡献集中度：自 2026-05-01 起 18,282 次提交中，awesomekling 7,575（41.4%）、kalenikaliaksandr 2,766、shannonbooth 2,034、sideshowbarker 1,259——前四人占 74.6%。近 100 个 PR 的合并分布同样收敛：除回灌 bot 外，合并方是 awesomekling(12)、kalenikaliaksandr(10)、gmta(8)、sideshowbarker(12 open)、Zaggy1024(6) 等 9 人，没有一个是名单外的新名字。
  • 但入口并没有完全焊死：sideshowbarker（HTML 规范编辑、WPT 侧的老牌外部贡献者）在近 100 个 PR 中有 12 个仍是 open，说明 maintainer 通道本质上跑在「已获信任者的 PR」上，而不是「关掉 GitHub 的 PR 按钮」——公告说「PR 只对 maintainer 开放」，实际形态是一扇只对熟人开门的窗口。
  • 外部人还剩什么：Calme1709 在近 100 个 PR 里恰好有 1 个、且未合并。这就是「公开贡献路径关闭」在数据上的全部残影。
  • 责任写得比授权更细：SECURITY.md 明确「maintainer 会视专业需要把常规贡献者拉进 triage 与修复」——即处置权可以外包，责任不外包；私人漏洞报告通道、版本号 + 平台 + 最小复现的报告要求、CVE 与协调披露时间线（若其他浏览器收到同一报告，取最长的约定披露期）全部写明，并且明说「暂不提供漏洞赏金」。它把「谁能进来」写成了负数条，把「谁担责」写成了正数条。

【L3 · 新人路径】

新人入口现在只剩三条：报 bug（浏览器内置「报告此站打不开」，崩溃报告先读再决定是否发送）、在 Discord 讨论、安全漏洞私下报告。代码路径已无。

用奥斯特罗姆的边界规则看：成员身份（membership）从「提交即可申请」改成了「被邀请」，监督与冲突解决机制（security triage、CVE 与披露时间线）却保留了下来并写得更细。也就是说，公地的门关上了，但公地的法庭还在开庭。

「开源之道」判断

这是一个把「责任与准入绑定」做到极致的样本，而它给出的理由，是整个 2026 年开源界正在被迫学会的那句话——AI 让「提交一份大 patch」不再能证明「作者付出了努力」。一旦这个信号失效，功绩制的输入端就坏了：你没法再按投入量给陌生人分配信任。

Ladybird 的处方不是修输入端（那需要漫长的时间与声誉积累），而是整体切断输入端，只从输出端招人：先成为 user、成为报 bug 的人、成为被 triage 的人，再被邀请进来。这在制度经济学上叫把不确定性的成本贴现给时间，而不是贴现给声誉体系。

代价很明确：一个从零写的浏览器引擎，从此只有 47 个具名贡献者的世界可供汲取（contributors API 全量 47 人；前四人占 3/4 产量），而它的安全面是全互联网。

用威廉姆森的四层看，这是 L2（许可与产权）一动不动、L3（治理与准入）做了重大改动、而压力来自 L1（技术环境——AI 改变了「努力」这个社会信号的含义）。

判断：制度健康度在「可追责」维度上明显变好，在「可接续」维度上明显变差——它现在能说清楚每一项变更由谁负责，但说不清再出现一个 Kling 时谁来接手。

下一个观察点有两个：① alpha 之后是否出现首批非既有 maintainer 的邀请（这是功绩制是否还在运转的唯一证据）；② 赞助结构里三个 Platinum（FUTO、Shopify、Cloudflare）与 DHH / 37signals 的人脉重叠，是否会导致「无发言权」这句承诺被要求兑现——公告写的是合同语言，合同语言只有在上游被审计时才作数。

📌 今日制度层归属与未来检验#

把今天两条主线落到 Williamson 的层次上：

  • L1 社会嵌入层（「努力」这个社会信号的含义正在改变）：论文测到人类提交变小、变少；Ladybird 直接承认「patch 大小不再能证明付出」。两者指向同一层——不是规则变了，是人们默认理解的东西变了。检验信号：一年内是否出现可机器验证的「人类劳动量」代理指标（而非只验证产出），例如强制的过程披露或口试式准入。
