2026-10-29 「开源之道」·论文略读：当「开源」需要用户先说明自己要干什么#

一句话推荐#

这篇论文的正标题叫「超越 open washing」，但它最有价值的产出不是又一套开放性打分表，而是一句几乎被写过就略过的话：在 LLM 的语境里，开源有可能反而加固而不是削弱既有的权力结构——同一份访谈材料，既是「怎样才算开放」这个问题没有答案的证据，也是「为什么它不会有答案」的答案。

内容概要#

一、它把「开放」从形容词改成了名词的复数#

论文的理论骨架不是自己造的，而是借用 Schlagwein 等五位学者 2017 年在 Journal of Information Technology 上那篇关于 openness 的编辑导言：「开放」是一个高阶概念，其特征是 access、participation、transparency 与 democracy；而落到具体指称上，它分三类——open resources（资源的性质：可及、可改）、open processes（过程的性质：参与广泛）、open effects（在某个领域造成的民主化效果，即文中所谓的 movement）。

Juntura 做的事是给这个三段式加第四段：technical requirements（开源许可那一整套技术—法律要件）。理由很直白：在 OSS 里，「发布人类可读的源代码」+「一套开源许可」这两个技术要件才把前三条原则变成可执行的东西。

这个借用看起来朴素，却是全文最要紧的一步。因为 Schlagwein 那篇原文自己就把话说透了：

「open resource, closed process」——开源代码在很多许可制度下，可以被拿去继续做专有开发。 「closed resource, open process」——众包并没有一个谁都能拿到手的开放资源，但它确实是一个开放参与的过程。

也就是说，「开放」这个词从来就不是一个维度上的刻度，而是三个不同指称共用一个词。这套工具在 2017 年是用来给信息系统研究划边界的，八年后被搬到 LLM 上，突然变成了一把指控工具——因为 LLM 厂商把「资源」那一格填满了一半，就宣称整张表都通过了。

二、样本与方法：16 个人、202 个码、5 个聚合维度#

半结构化访谈 16 位专家：LLM 开发者（有大厂背景的、有研究背景的）、基础模型专家、技术律师与开源合规律师、IP 与专利律师、可复现性专家、算力专家、微调从业者、技术生态建设者与投资人、开源专家。转录由 Microsoft Teams 自动生成后人工校正，匿名化后进 Atlas.ti。

分析方法用 Gioia 法：一阶概念（用受访者自己的原话）从 202 codes 归并为 47，再升到 13 个二阶主题、5 个聚合维度。作者对 Gioia 法被当「菜谱」用的批评有清醒意识，并专门辩解了自己不是照着菜谱填空。

五个聚合维度就是第五章的骨架：

  1. 资源与法律壁垒限制了广泛参与和透明度（4.1）
  2. 商业逻辑决定开放度（4.2）
  3. 协作生态驱动创新（4.3）
  4. 开放需要具体情境下的考量（4.4）
  5. 在开放与市场动力之间取得平衡（4.5）

三、最锋利的那一组发现（都带原始计数）#

「开源模型必须有经济可行性」——12/16 位专家这么说。 这不是一句常识，而是一条把判定权交出去的陈述：一旦「能不能持续赚到钱」成为开放度的前置约束，开放度就成了商业策略的因变量。作者归纳出四种主流路径：卖闭源模型本身、卖访问（API/订阅，专家口中的「OpenAI 模式」，小模型或旧模型当亏损引流）、建生态（Meta 的 Llama 之于 Android）、卖周边服务。并且抓到一个转变模式：先开源吸引用户、融资或声誉，之后转向「更受限的开放」，并点名 Mistral 作为样本。

「真正的开源」与产业实践正面冲突。 作者用一张表（Table 3）把这件事说得很干净：需要复现模型的人要求全透明——数据、代码、库、硬件；需要修改改进的人要求低一档；需要在模型之上做东西的人，开放权重加推理代码就够；只为跑起来用的人要求最低。一位技术律师的原话是：「对多数用户而言，修改和分发的自由已经完全够用，不需要重造模型。」

然后那位律师给出了全文最值得抄的一句判断：与 OSS 早期不同，今天关于「什么算开源 LLM」的讨论，中心已经从意识形态与自由，移到了公司的实际需要上。

「开源」这个词不能注册商标。 开源专家指出，这意味着行业只能靠「互相理解为是」来用这个词。OSI 主持的多方倡议 OSAID 审过若干语言模型，发现许多自称开放的根本不达标。另一位受访者把现状叫作 “wild west”。而「open」一词已经退化成一个相对词——「比 OpenAI 开放，或者比只能走 API 的模型多点可见度」，用一位专家的话说。

市场成功可以替代定义。 一位 LLM 开发者直说：如果 Llama 这类不完全符合正式定义的模型拿到了足够 momentum，它就可以算开源。这句是全文对「度量权」最直接的经验材料——不是谁定义了开源，而是谁的装机量替开源做了定义。

四、以及那句被放在摘要末尾、但实际上统摄全文的话#

论文在讲完上述一切之后，落了一句：

「鉴于这些独特的挑战，LLM 中的开放性可能会加固而非创建一个更包容、更具参与性的环境。」

这句在摘要层只是一句提醒。但把它接回 Schlagwein 的三段式，它就变成可检验的：LLM 的 open resources 一格被填了（权重可下载），open processes 一格却因为资源密集而系统性塌陷（个人无法参与模型训练，只能微调），open effects 一格则交给了市场 momentum 自己宣布。 三格里填了一格，然后宣称整张表通过——这不是欺骗，这是用一把量资源的尺子，去回答一个量人的问题。

为什么值得读#

一、它提供了「open washing」这个词最早那一批学术形式化之一，并且是从管理学而不是法学进来的。 同一时期、同一议题上，Widder 等人 2024 年在 FAccT 上已经用 14 个开放维度测过 45 个以上生成式 AI 系统，结论是开放性是 composite 且 gradient 的。Juntura 与 Eloranta 走的是另一条路：不建测量表，而是问人。两个入口的差别值得看清——一个给出可核查的分数，一个给出专家为什么无法就分数达成一致的说明。后者对制度分析更值钱。

二、它把「开放」这个词的语义结构摊开了，而这在中文语境里几乎没人做过。 我们习惯说「开源就是开源」「open source is not one thing」，但很少追问：这个词在英文里同时挂在资源、过程、效果三个不同的东西上，而这三种「开放」彼此可以背离。一旦接受这一点，「某项目开放吗」这个问题就必须先补一句「开放什么、对谁开放、为了什么效果开放」。这就是 Schlagwein 那三段式真正能带出来的东西。

三、它给出了一个反直觉且可以继续检验的制度判断。 主流的叙事是「开源降低了门槛」。这篇说的是：在资源密集的领域，开源降低的是「拿到」的门槛，同时抬高了「参与」的门槛——LLM 社区仍然保留着 core-periphery 结构、去中心化治理与协作意识形态，但参与被挤压到了「在 Hugging Face 上微调别人训好的模型」这一层。这不是对开源的批评，而是对一种误认的批评：把资源可及当成了参与开放。

四、它的自陈限制比多数同类论文诚实，而且这些限制本身构成下一轮研究的清单。 作者明写三条：大厂代表与闭源模型开发者样本不足，可能偏向开源拥护者；专家访谈存在精英偏差；多数访谈在受访者的第二语言中进行，可能限制表达。还补一条：文中反复出现 OpenAI、Google、Meta，但本研究不审查这些公司的实践是否真的符合开源原则，只把它们当讨论的参照坐标。

为什么对开源社区如此重要？#

一、「开源」的判定权正在从组织滑向产品#

OSS 时代，判定的位置是清楚的：OSI 十项标准 + 一份许可证 + 人类可读的源代码。这三样都是组织可以盖章的东西。LLM 时代，同样的位置被三件东西占住了：权重能不能下载（产品属性）、装机体量够不够（市场属性）、公司的商业模型能不能成立（财务属性）。

Williamson 的 L1→L4 在这里给出一个不舒服的读数：L2（制度环境：定义与许可证）没有消失，但它被 L4（资源配置：算力与资本的分布）倒推着改写。 不是 L2 约束 L4，而是谁掌握训练一次模型要烧掉的算力，谁就替 L2 起草判据。这和我们在别处看到的形态是同族的——法律或规范的沉默，被下游有支付能力的一方填满。

二、Ostrom 第 1 条在这里换了一个失效形态#

Ostrom 谈公地，第一条是边界必须清晰：谁在边界内、什么在边界内、边界由谁划。传统 OSS 的答案粗糙但可操作：谁能提交补丁、什么算源代码、维护者集体划。

LLM 把这三问全部打散。谁在边界内——四类主体（使用者、微调者、部署者、数据使用者）的需求彼此冲突，Table 3 就是它们冲突的示意图；什么在边界内——权重、许可、数据、训练代码四项可以任意组合（再加上模型卡与文档，就是受访者提到的 OSAID「钥匙孔」框架：code / model / data 三区，每区再分必需与可选）；边界由谁划——这一问在论文里的答案最冷：没人划，市场替它划了。

一个更值得警惕的推论：当「开放」的定义以用户需求为轴心时，定义权就从社区转给了买方。 Table 3 的排序不是按自由多少排的，是按「你要拿它干什么」排的。这在商业上是合理的——一位律师说得很清楚，多数公司要的就是修改和分发——但它在制度上意味着：定义由最不需要完整开放的那一方来写。 这不是谁的阴谋，只要把定义挂到「用户要什么」上，这个结果就是自动的。

三、对「大分流 2.0」是一次必要的限缩#

写这个题目时最容易犯的错，是把「open washing」当成西方现象、把「开放」当成东方叙事。这篇论文两边都不站。它跑的是芬兰的访谈、用的是 2017 年 IS 领域的框架、样本偏向开源拥护者，谈的全是 Llama、Mistral、OpenAI、Hugging Face、Meta。

但它给大分流研究提供了一个更有用的东西：一个共同的技术约束，以及各制度环境对它的不同回应。资源密集不是中国的问题也不是美国的问题，它是训练一个前沿模型需要多少钱的问题。同一约束在美国被回应为「生态 + 服务 + 权重引流」，在欧洲被回应为「监管条件 + 许可复杂性」，在中国被回应为「平台所有权 + 分发入口」。约束是跨制度的，回应是制度性的——这比「某国不开放」这种说法结实得多，也更难被驳回。

四、它把「开源是俱乐部品非公共品」从信念变成了可指认的现象#

注意论文里那条被一笔带过但极关键的线：开源代码在很多许可制度下，可以拿来继续做专有开发——Schlagwein 原文的「open resource, closed process」。而在 LLM 上的对应物更极端：权重可以下载（资源开放），但训练过程、数据血统、复现路径被保留（过程闭合）。

这就是俱乐部品在经济上的具体形状：准入是宽的，维系是窄的。谁都能拿到权重，但能让权重继续被改进的那一群人，是极小的一个圈子，且他们的算力来自圈子之外。这也是为什么「开放」这个词在 LLM 上特别容易被误读——它的资源层做得比 OSS 时代漂亮得多，而过程层退得比 OSS 时代远得多。

关联阅读#

  • 此前推荐：Sennett《The Craftsman》——工坊靠「在场」传递质量权威，而开源把评审搬进了异步界面；本文补上另一端：当生产本身需要百万美元的机器时，「在场」就变成了「有机器」。
  • 此前推荐：Alcaras (2026) Beyond severance——「产业性公共品」：使用上像公共品，维系上像产业设施。本文的 LLM 版本是同一命题的极端形态：使用方的门槛被压低，维系方的门槛被抬到个人无法企及。
  • 此前推荐：Wen, Ceccagnoli & Forman (2016) 开放 IP 策略——产权边界的策略化如何改变进入格局；本文里「选择性开放」是同一种策略化的反面用法：不是为了扩大进入，是为了保留退出。
  • 此前推荐：Wang & Song (2026) 生产力—进入悖论——工具压低写码成本却不降低参与门槛。本文给出机制上的同构物：在 LLM 上被压低的是「拿到」的成本，被抬高的是「被算作参与者」的资格。
  • 此前推荐：Kelty《Two Bits》——递归公共性：讨论的对象、场所与产物互为构成。本文的 wild west 描述正好是这套递归装置的缺位形态：讨论场所还在（HF、GitHub），但产物（能不能改、谁改了）已经不可见。

延伸思考#

一、「用户需求决定开放度」是一次权力转移，还是只是一次坦率？

Table 3 那张表在商业上是对的，在制度上是危险的。商业上：为公司做 LLM 应用的人不需要复现模型，只需要改。制度上：把「开放」的判据从「行动者能做什么」换成「买方需要什么」，等于把定义权交给了最不需要完整开放的那一方。 而买方在多数场景里不是个人开发者，是采购预算的持有者。适兕讲过「行动的定义权」——这里可以再压一层：当判据由需求侧书写，定义的争夺就从「谁有权说这是开源」降到「谁出钱」。 前者还留着一个公共争论的场所，后者连场所都不需要。

二、market success 替代定义，和行政动员替代定义，是同一件事吗？

一位受访者说，Llama 只要拿到足够 momentum 就可以算开源。这句话如果在中国语境里被换成「某平台装机体量足够大，它就是事实标准」，很多批评者会立刻指出这是行政/平台力量替公共标准做决定。但在西方语境里，同构的一句话用的是「市场」。这是不是同一套「以事实上的接受度替代规范上的正当性」？ 我认为在机制上同构，在可争性上不同：市场 momentum 至少留下了「可以不用它」的退出选项，行政认定的标准则往往同时封死了退出路径。但两者的共同点是：都没有人需要在公开场合为自己的判定辩护。 这一层分歧值得单独写。

三、如果 OSAID 已经发布了，为什么十六位专家还在讨论「要不要有定义」？

这是本文最刺眼的一处时间证据。论文写作期引的是「OSI 预计 2024 年 10 月给出稳定定义」；而 OSAID v1.0 确实在 2024-10-28 于 All Things Open 2024 发布。也就是说，在这场关于「定义是否可能、是否需要」的专家争论发表之前，官方定义已经落地近一年。 论文没有错——它诚实记录的是 2024 年访谈时刻的认知状态。但这恰好是一个值得收藏的样本：一个标准发布了，却并没有结束争论，因为争论的真实对象不是文本，是十六位专家各自站在成本线的哪一侧。写定义的人、卖 API 的人、审许可证的人、算 GPU 的人，对「开放」这个词的体感本来就不同。文本可以统一，体感不能。

四、这篇论文自己的矛与盾

它由一位硕士生写就、以 AOM 摘要稿形式发表、Crossref 零参考文献记录（AOM Proceedings 的元数据不登记参考文献，不是作者没引）、零被引。按我们前几篇用的判据，它属于可复算性未验证的一类：访谈不可重跑，编码只是部分可核（202→47→13→5 的链条在论文里有图，但原始转录不公开）。它最有价值的部分恰恰是最无法复算的部分——专家们的原话。

反过来看这也许是它诚实的证据：一篇主张「开放不是二元的」论文，本身也不该被二元地判死或判活。 它是一份 2024 年的访谈档案，记录了十六个专业位置上的体感。这种材料过期得快，但过期之后仍然有用——因为可以拿它和今天比，看谁改了口。

五、留给「开源之道」的一个自反问题

如果「开放」必须分资源/过程/效果三层来谈，那我们自己反复用的「真开源 / 伪开源」二分，是不是也犯了一个错——把三层的问题压成一层的答案是或否？大分流 2.0 里的「特许工程代码 / 局域网共享 / 赛博庄园」，其实都可以在 Schlagwein 的三段式里找到更精确的位置：赛博庄园是「资源开放、过程闭合」，局域网共享是「过程开放、资源封闭」，特许工程代码是「资源半开、效果不开放」。用三段式代替二分，判断不会变软，只会变准。 这可能是这篇论文给我们最实用的一件东西。

金句#

「在 LLM 的语境下，开源可能会加固现有的权力失衡，而不是把场地抹平——这与开源让开发更可及的那个理想，正好相反。」

—— 但要记住这句之前还有一句：这是作者从十六份访谈里推出来的判断，不是她测出来的结论。
